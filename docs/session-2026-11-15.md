# Session Record — 2026-11-15

## Purpose and current state

This session mapped the Open Book Builder repository against the hardware, purchasing data, firmware, and work needed to build **ten readers in the United States**. Read the [detailed hardware review](hardware-build-review-2026-11-15.md) for evidence and the [handoff](handoff-2026-11-15.md) for continuation details. No board was built, firmware compiled, vendor quote obtained, order placed, or application/BOM data corrected. Prices and stock are dated observations, not a purchase-ready budget.

## Decisions made

- Start with existing Open Book PCB revisions and compatible parts. Versions **1, 2, and 3 share one PCB design**; their optional population, firmware, content, included parts, and quantities remain to be defined after feature exploration.
- Defer Wi-Fi, Bluetooth, touch, and cases for the first ten. Use physical buttons and original Pico **SC0915** as the non-wireless reference. Wireless and touch remain future options.
- Treat the product as a small-batch artisan reader. Minimize the user's hand soldering and rework. Compare a **one-unit pilot then nine** against **ten together**, with factory C1 assembly and complete C2 modules priced as the preferred route. No vendor quotes exist yet.
- Build a complete checklist for each configuration: fabrication, board assembly, parts, display, microSD, batteries, spares, shipping, tax, setup fees, and one-time tools. The user owns no Open Book parts, has a basic iron and hand tools but no multimeter, and has a Micro-USB data cable and microSD reader. They can flash firmware, prepare cards, connect displays, install batteries, and check units on Linux.
- Use **text first** for the first ten. Custom, versioned Markdown is the collection source; convert it to a Pico-ready text file for the first pilot. Inline images, diagrams, and scanned pages can wait. Flag unsupported visual content during import. Native Markdown and EPUB remain later options.
- Assign categories and tags in collection metadata before download; the reader uses them for filtering and sorting without an on-device editor. Store favorites and reading progress on each microSD card, so state follows the card. The user plans a site for downloadable books, articles, and documents; Linux-to-microSD transfer is the proposed first-batch path.

## Findings that block an order

1. The app labels **SC0918 Pico W** as equivalent to original Pico SC0915. The firmware configuration names `board = pico`; Pico W compatibility was not established.
2. The app's Pico SDK and font-flasher instructions conflict with upstream's PlatformIO build and `babel.bin`-on-microSD first-boot workflow. Firmware PRs #10 and #11 were open at review time; their combination has not been built or tested here.
3. The 1022C battery retainer is missing from the C1 BOM. The Digi-Key export includes C2 internal components even when a complete C2 module is assumed. Circuit descriptions for Q1/Q2, R1–R4, connectors, and side buttons disagree with PCB nets.
4. The app models C1-06 silkscreen and C2-02 data while directing users to C1-05 and C2-03 fabrication routes. Electrical/layout equivalence has not been shown. C1-05 Gerbers lack an assembly-ready C1 BOM and placement file.
5. The candidate replacement GDEY042T81 display has an unresolved driver-circuit/firmware pairing: its manufacturer reference values differ from published C2 BOM values. Two checked Good Display storefront listings showed zero stock; ten panels have not been sourced. A touch model exists but requires a separate flex connection and is deferred.
6. The displayed **$43.27 per-unit** subtotal omits major build costs. A partially refreshed **$180.92 for ten** excludes displays, C1/C2 fabrication and assembly, cards, batteries, spares, tools, freight, and tax; $71.70 still uses old small-part prices. Conflicting C2 $30–80 estimates have no quote.
